8. ¿Puedes explicarme con calma cómo funciona git rebase y cuándo es mejor usarlo que merge, porque en mi equipo siempre discutimos por esto y nunca llegamos a nada?

Git rebase reescribe tu rama para que parta de la punta más reciente de otra, como si hubieras empezado tu trabajo ahí. Cada commit se reaplica uno a uno, con hashes nuevos. Merge, en cambio, no toca tu historia. Crea un commit extra que une las dos ramas, conservando la forma real de lo ocurrido. Usa rebase para limpiar tu rama local antes de compartirla, y merge para integrar ramas ya publicadas. Regla de oro: nunca reescribas commits que otros ya tengan.
