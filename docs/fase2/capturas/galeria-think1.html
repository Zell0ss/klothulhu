8. ¿Puedes explicarme con calma cómo funciona git rebase y cuándo es mejor usarlo que merge, porque en mi equipo siempre discutimos por esto y nunca llegamos a nada?

Git rebase reescribe tu rama para que parezca que partiste de la punta actual de otra. Merge, en cambio, crea un commit nuevo que une las dos historias. Rebase deja un historial lineal y limpio, pero cambia los hashes de los commits, así que no lo uses sobre ramas que otros ya compartieron. Merge conserva la historia tal como ocurrió, con sus ramas y sus desvíos, aunque el grafo quede enredado. Regla práctica: rebase para tus ramas locales antes de abrir un PR, merge para integrar ramas compartidas. Ahí tienes la paz, mortal.
